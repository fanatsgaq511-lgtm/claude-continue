# Claude Continue — облачный запуск через GitHub Actions

Проект открывает последний доступный диалог Claude в браузере Chromium и отправляет ровно одно сообщение `Continue` в заданное локальное время.

> **Ограничение точности:** GitHub Actions — планировщик с best-effort запуском. Cron может стартовать с задержкой в несколько минут (иногда больше), поэтому гарантировать отправку ровно в 03:50 нельзя. Скрипт ждёт целевое время внутри runner; если cron стартовал с опозданием до 20 минут, отправляет сразу. При большей задержке этот запуск переносится на следующий день и обычно завершится по тайм-ауту. Для точности до минуты используйте постоянно работающий VPS с systemd timer или облачный сервис с планировщиком и постоянным браузерным профилем.

## Что потребуется

- GitHub-аккаунт и репозиторий.
- Компьютер только для первоначального входа в Claude и получения файла сессии. В момент отправки компьютер может быть выключен.
- Python 3.11+ для подготовки сессии.
- Аккаунт Claude, в который вы можете войти обычным способом.

## 1. Подготовить авторизованную сессию

На своём компьютере распакуйте проект, откройте терминал в папке проекта и выполните:

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate

pip install -r requirements.txt
playwright install chromium
python save_session.py
```

Откроется окно Chromium. Войдите в Claude вручную на `https://claude.ai`, при необходимости завершите обычную проверку входа, затем вернитесь в терминал и нажмите Enter. Скрипт сохранит `session_state.json` и выведет строку Base64.

**Не публикуйте `session_state.json` и Base64.** Они дают доступ к вашей сессии. Не отправляйте их никому и не добавляйте файл в Git.

## 2. Добавить GitHub Secrets

Создайте GitHub-репозиторий и загрузите в него содержимое ZIP (без `session_state.json`).

В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте:

- `CLAUDE_SESSION_B64` — вся Base64-строка, которую вывел `save_session.py`.
- `CLAUDE_TIMEZONE` — `Europe/Moscow` (необязательно, это значение по умолчанию).
- `CLAUDE_SEND_TIME` — `03:50` (необязательно, это значение по умолчанию).

Секрет сессии можно обновить в любое время, повторно запустив `save_session.py` и заменив значение GitHub Secret. Сессии Claude могут истекать; тогда потребуется новый снимок сессии.

## 3. Включить workflow

В GitHub откройте **Actions** и разрешите запуск workflows, если GitHub попросит. Workflow `Claude Continue` запускается по расписанию и вручную.

По умолчанию cron установлен на `50 0 * * *` — это 03:50 в `Europe/Moscow` при UTC+3. Время cron GitHub задаётся в UTC. Если меняете время отправки, измените одновременно:
1. Secret `CLAUDE_SEND_TIME` (формат `HH:MM`);
2. строку `cron` в `.github/workflows/continue.yml`, переведя целевое время в UTC для нужной даты/сезона.

Для `Europe/Moscow` сейчас используется UTC+3: например, 04:15 по Москве = `15 1 * * *` в UTC. Для зон с сезонным переходом на летнее/зимнее время cron сам часовой пояс не отслеживает — потребуется корректировать UTC cron при смене сезона.

## 4. Проверить вручную

Для теста не нужно ждать 03:50:
1. В GitHub откройте **Actions → Claude Continue → Run workflow**.
2. Выберите `workflow_dispatch` и запустите.
3. Workflow выполнит отправку сразу (ручной запуск не ждёт ежедневного времени).
4. Откройте Claude и проверьте, появилось ли `Continue` в последнем диалоге.

**Важно:** ручной тест отправляет реальное сообщение. Запускайте его только если действительно хотите отправить `Continue` сейчас.

## 5. Как работает проект

- `save_session.py` открывает обычный Chromium, ждёт ручного входа и сохраняет Playwright storage state.
- GitHub Actions получает state только из GitHub Secret и записывает его во временный файл runner.
- `run_continue.py` применяет заданную временную зону через `zoneinfo`, открывает Claude, проверяет авторизацию, выбирает верхний диалог в боковой панели, вводит `Continue` и отправляет.
- После выполнения workflow удаляет временный файл состояния.

## Ошибки и ограничения

- **Нужен повторный вход / редирект на login:** сессия истекла. Повторите шаг 1 и обновите `CLAUDE_SESSION_B64`.
- **Не найден диалог:** откройте Claude вручную, убедитесь, что нужный диалог виден в истории, затем обновите сессию и повторите запуск.
- **Не найдено поле ввода или кнопка отправки:** Claude мог изменить интерфейс. Проверьте лог workflow; потребуется обновить локаторы в `run_continue.py`.
- **Два запуска одновременно:** workflow использует concurrency group, чтобы не запускать два job параллельно.
- **Нет гарантии ровно в 03:50:** GitHub Actions не является real-time планировщиком. Фактическое начало может запаздывать. Также интерфейс Claude может быть недоступен или отклонить автоматизированную сессию.

## Более надёжная облачная альтернатива

Для более предсказуемого времени используйте небольшой постоянно работающий VPS (например, Ubuntu) с Playwright и `systemd` timer, настроенным на `Europe/Moscow`. VPS остаётся включённым, а ваш компьютер — нет. Даже VPS не гарантирует абсолютную точность до секунды, но обычно позволяет контролировать запуск лучше, чем GitHub Actions. Секреты храните в защищённом файле окружения с правами доступа только владельцу; не помещайте cookie в репозиторий.

## Безопасность

- Не добавляйте `session_state.json` в Git.
- Не выводите содержимое сессии в Actions logs.
- Используйте приватный репозиторий.
- Если секрет случайно попал в лог или репозиторий, удалите/отзовите сессию выходом из Claude на всех устройствах и создайте новую.
